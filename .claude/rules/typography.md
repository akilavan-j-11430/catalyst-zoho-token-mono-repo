# Typography

`globals.css` is the only file in this app that names a font family. Nothing else sets
one - not a component, not a wrapper, not a utility class.

Three steps, each in one place:

```
layout.tsx      next/font/google loads Geist, exposing --font-geist-sans / --font-geist-mono
globals.css     @theme inline maps those onto --font-sans / --font-mono
globals.css     body applies font-sans once, and everything inherits it
```

```css
/* apps/web/src/app/globals.css */
@theme inline {
  --font-sans: var(--font-geist-sans), ui-sans-serif, system-ui, sans-serif;
  --font-mono: var(--font-geist-mono), ui-monospace, monospace;
}

@layer base {
  body {
    @apply bg-background text-foreground font-sans;
  }
}
```

The fallbacks matter: a `--font-sans` that resolves to a single failed variable resolves to
nothing at all.

## Never set a family on a component

No `font-family`, no `style={{ fontFamily }}`, no `font-[...]` arbitrary utility, and no
second `next/font` loader. A design that needs a different face earns a token in
`globals.css`; a component then uses the token or inherits it.

The comment at `globals.css:83-86` is the worked example of why. The generated template set
`body` to Arial, which outranked the Geist variables, and every wrapper had to re-apply
`font-sans` as a repair. One family named in one place is what removed all of them.

`src/components/ui/` is vendored shadcn, regenerated by `shadcn add` and never hand-edited,
so the `font-sans` on `ui/sonner.tsx` stays where upstream put it. Restyle through the
tokens instead.

## Size and weight are not font choices

`text-sm`, `font-medium`, `tracking-tight` and `leading-none` are the Tailwind scale, and
a component picks from it freely. This rule is about families only - which typeface the app
speaks in, not how large a given line is.

## The sign-in iframe

`public/catalyst_signin.css` is the one file that names a family twice, and it has to.

It styles the Catalyst IAM widget, which is a separate cross-origin document. It cannot
read this document's custom properties, so its `--app-font` is a literal stack rather than
a `var()` reference, and it declares its own `@font-face`.

That face is loaded from `fonts.gstatic.com`, not from `/public`. `@font-face` always
fetches with CORS; `/public` sends no `Access-Control-Allow-Origin`, so a self-hosted copy
is blocked and silently falls through to the next entry in the stack - which looks almost
right, and is the failure mode to watch for. Google's CDN sends `*`.

Three things must stay in step by hand when the app's typeface changes:

1. the `next/font` loader in `layout.tsx`
2. the `--font-*` tokens in `globals.css`
3. the `@font-face` and `--app-font` in `public/catalyst_signin.css`

Verify the third by rendering the widget and looking at it. A green build says nothing
about which face the iframe actually got.
